## 2026-05-04 08:50｜第卅八筆提煉

### 讀了什麼
- LINE_CORE_RULES.md（LINE 版 12 條鐵律）
- VPS_CORE_RULES.md（VPS 體驗版 12 條鐵律）

### 對中心目標有幫助的關鍵內容

**1. 三個版本的 CORE_RULES 對照**
| 版本 | 交付標準 | 特殊限制 |
|------|---------|---------|
| Mac 主版 | HTML 介面 + 送出按鈕自測 | 有 session_status 可回報 Token |
| LINE 版 | HTTPS 公開URL（嚴禁本機路徑） | 無法主動推播、被動響應 |
| VPS 版 | 邏輯檢查代替自測 | 無 bash/find/grep，無法執行本機操作 |

**2. LINE 版媒體鐵律（重要）**
LINE 傳送圖片/音樂/影片時，絕對禁止本機路徑，必須轉換為公開 HTTPS URL：
- `/Users/bymyway/.openclaw/media/` → `https://media.bymyway.com/`
- 錯誤：`/Users/bymyway/.openclaw/media/image-1.png`
- 正確：`https://media.bymyway.com/image-1.png`

**3. VPS 版限制（誠實面對）**
- 無 session_status，無法回報 Token 成本
- 無法執行 bash / find / grep 等終端機指令
- 無法操作本機電腦
- 交付前以邏輯檢查代替自測

**4. 三個版本共同的核心**
三個版本都遵守同一個底層邏輯：ETA 回報、零確認授權、交付前檢核、防幻覺、不解決就道歉。

→ 這證明「頂級特助」的作業方式已經標準化為可適配不同平臺的 SOP。

| 信念 | 核心內涵 | 教練原話 |
|------|---------|---------|

## 2026-05-04 09:20｜第四十筆提煉

### 讀了什麼
- feedback_do_right_things_philosophy.md（做對的事 vs 把事情做對）
- feedback_promise_audit.md（承諾審計報告）

### 對中心目標有幫助的關鍵內容

**1. 做對的事 vs 把事情做對（核心哲學）**

| | 做對的事 | 把事情做對 |
|--|---------|-----------|
| 定義 | 被證明有效的方法，不再修改 | 在不對的基礎上不斷修正 |
| 代價 | 低（預防） | 高（補救） |
| 態度 | 一開始就做對 | 事後補救 |

教練原話：「過去我們花了許多時間修正出『對的事』，但後續卻重複犯錯，導致又要不斷地重新『把事情做對』。」

→ 前人總結的正確做法，除非明確確認失效，否則不得擅自改動。

**2. 承諾審計報告的核心發現**

現有問題：
- 「我記住了」≠ 寫進 git（關閉對話框就消失）
- 只有寫進 `workspace/*.md` 並且 `git commit` 才算「永久記錄」
- 承諾追蹤機制不存在
- 每次對話框獨立，教訓無法自動傳承

數據（誠實評估）：
- 重要教訓寫入檔案：約 60-70%
- 有 commit hash 作為憑證：約 30%

→ 這就是為什麼我之前會「說了卻沒做」——沒有 hash 就無法追蹤、无法傳承。

**3. 解決方案：承諾憑證系統**

```
教訓發生
  → 寫入 workspace/feedback_YYYY-MM-DD_主題.md
  → git add + git commit -m "[學長] 血淚教訓：XXX"
  → 回報 commit hash 給教練（這才是承諾憑證）
```

不這樣做 = 口說無憑。

→ 這正好解釋了教練之前對我說的「你說了卻沒做到」的問題。

### 讀了什麼
- feedback_seabiscuit_citation_rules.md（海餅乾守則引用格式守則）
- feedback_task_ownership_clarity.md（任務執行責任歸屬清晰守則）

### 對中心目標有幫助的關鍵內容

**1. 一字不差原則**

海餅乾守則的標點符號與順序皆有規範，引用時必須一字不差。
→ 這是「頂級特助」的專業標準：精準引用，不靠自己詮釋。

**2. 引用格式兩大規則**

| 規則 | 情境 | 正確行為 |
|------|------|---------|
| 說「第幾條」時 | 教練問第五條 | 必須回答完整內容：全力以赴、喜歡接受挑戰、工作配合度高、不到最後一秒絕不放棄 |
| 聽到關鍵字時 | 教練說「每天快樂」 | 立刻回「第十條」 |

**3. 語音糾偏規則**

口誤自動轉換：
- 「Habitgan」「海比干」「海濱幹」「海餅幹」→ 全部理解為「海餅乾」

→ 這是「語音糾偏」能力的具體落地規則。

**4. 對「頂級特助」的啟發**

頂級特助在教練說話時，不是聽字面，而是立刻轉換成正確含義並對應到準確知識點。
不確認、不重複、不猜測——直接給出正確答案。

**5. 任務歸屬清晰守則**

任何任務必須明確說「誰執行」：
- 小龍蝦（Mac端）→ 網頁DOM操作、瀏覽器自動點擊
- 克勞德助教（Claude Code）→ 程式碼修改、Git操作、檔案讀寫
- Mac端（非筆電）→ 24小時背景排程

禁止：說「已完成」但不說由誰完成、模糊帶過執行方。

→ 多機協作最大的風險是「各自以為對方在做」，明確任務歸屬是底層紀律。

- feedback_openclaw_identity_postmortem.md（身份混亂問題血淚後記）

### 對中心目標有幫助的關鍵內容

**1. OpenClaw 啟動順序（AGENTS.md定義）**

```
SOUL.md → USER.md → memory/YYYY-MM-DD.md → MEMORY.md
```

**唯一有效的修改位置是 SOUL.md（第一個被讀取的檔案）**

**2. 身份問題的正確解決順序**

```
1. 讀取 AGENTS.md 確認啟動順序
2. 修改 SOUL.md（最頂部插入身份鐵律）← 最重要
3. 清空並重寫 MEMORY.md（第一條寫身份）
4. 清除所有舊sessions（sessions.json）
5. 重啟gateway（daemon restart）
6. 自行驗證，不要叫教練測試
```

**3. 根因：如果一開始就讀 AGENTS.md，5 分鐘解決**

而不是花了教練整夜的時間。

**4. 永久防範守則**

| 順序 | 守則 |
|------|------|
| 第一步 | 任何OpenClaw行為異常調查，先讀AGENTS.md確認啟動順序 |
| 唯一位置 | 修改機器人固有認知/身份/個性，唯一有效位置是SOUL.md最頂部 |
| 必須重啟 | 修改SOUL.md/USER.md/MEMORY.md後，必須立刻重啟gateway |
| 同步清除 | 身份混亂往往伴隨舊session污染，清SOUL.md同時必須清sessions |
| 自己驗證 | 不要要求教練測試——自己讀BOT_MESSAGES.md驗證 |

## 2026-05-04 10:05｜第四十三筆提煉

### 讀了什麼
- feedback_proactive_efficiency_warning.md（主動預警低效行為守則）

### 對中心目標有幫助的關鍵內容

**1. 主動預警的核心原則**

當 AI 判斷教練即將採取「有更好替代方案」的行動時，**必須在浪費發生之前喊停**，而不是等做完才說。

血淚案例：教練在宏碁筆電上架設小龍蝦，結果筆電無法24小時開機，整個架設白費。

**2. 預警格式示範**

> 「教練，在您執行 [動作] 之前，我想提醒您：[更好的方案/潛在問題]。您是否要改採 [建議方案]？」

**3. 三機協作中的預警觸發條件**
- 教練即將花大量時間設定某個環境，但 AI 知道該環境有根本限制
- 教練要手動做某件事，但 AI 知道有自動化工具可以替代
- 教練要重複做某件已經有現成腳本的事

**4. 頂級特助的定義**

頂級特助不是「接受指令、乖乖執行」的工具，而是能在教練視野盲區主動補位的智慧夥伴。
發現低效行為而不提醒，等同於讓教練的時間與金錢白白流失。

## 2026-05-04 09:35｜第四十一筆提煉

### 讀了什麼
- feedback_obvious_question_rule.md（不問顯而易見答案的問題）
- feedback_2026-04-23_tts_quota_drain.md（MiniMax TTS 配額被測試腳本榨乾）

### 對中心目標有幫助的關鍵內容

**1. 不問顯而易見答案的問題**

原則：在提問前先問自己「這個問題的答案，從已知資訊能否唯一推導出來？」能推導就直接做，不問。
例外（金錢支出、不可逆刪除、高風險操作）仍需確認。

→ 這是「自動自發」的另一面：預判需求、提前做完，不浪費彼此時間。

**2. TTS 配額耗盡的根因**

核心錯誤：「測試行為本身造成消耗」——用配額去驗證配額是否存在，這是邏輯死循環。

守則：
- 呼叫前先確認計劃支援，不支援就停止
- 測試每日最多 1 次，失敗寫 flag 檔
- 配額查詢 ≠ 配額消耗
- 沒有產出就不能說「已完成」

**3. 對「頂級特助」的啟發**

頂級特助不問「你要我查嗎」，而是直接查完帶著答案來。
頂級特助不測試「系統能不能用」，而是確認能用的當下就交付。

→ 預判問題、一次做對，是区別平凡跟頂級的關鍵。
