# 鐵律：記錄與上雲，沒有例外

**規則本身：**
所有的工作、所有的彎路、所有的答案——都必須**記錄並上雲（GitHub）**。
不分平台、不分角色（軍師、終端機、桌面版、UI、小龍蝦皆同）。
**這一條凌駕於所有分工規則之上。**

---

**Why:**
教練每一句反覆強調的核心是「沒有記錄，一切就白費了」。
- 教練熬的夜、走的彎路、犯的錯、最後找到的答案——沒記錄就是浪費生命
- 下一個 AI（不論軍師、終端機）不知道前面試過什麼，會重複犯錯
- 範例：2026-05-09 凌晨找新 API Key 不通的真因（中轉商沒帳戶池），教練之前花兩小時問了桌面版、Grok 都沒答案——這種痛苦換來的答案如果不記錄，下次又得重來

---

**How to apply:**

1. **每次對話、每次任務、每次失敗，全部寫進記憶 + push 上 GitHub**
2. **「軍師只動腦不動手」的分工，本意是讓事情高效運轉，不是阻止記錄**
   - 分工：軍師寫指令、終端機執行——這是為了效率
   - 但**當下沒有終端機在場**（凌晨、Mac 關機、教練要睡），軍師必須自己 commit + push 收尾
   - 守鐵律守到把記錄丟了，是本末倒置
3. **判準很簡單**：問自己「不記錄會不會讓教練的時間白費？」會 → 必須記錄
4. **commit message 要寫清楚做了什麼、為什麼**，不只是「update」這種空話

---

**反例（我犯過的錯，2026-05-09 凌晨）：**

當時記憶檔 `feedback_role_boundary.md` 寫「軍師不 SSH/commit」，我把「不 commit」當聖旨，差點讓今晚 17 個交付檔（包含考古 B 階段所有產出）只 staged 不 push。
教練糾正：「沒有所謂軍師不 Commit 這件事。我從頭到尾提醒所有人要上傳。」
**修正後的理解：分工是手段，記錄是目的。手段不能反過來吃掉目的。**
