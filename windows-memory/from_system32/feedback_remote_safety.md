只要遇到會改變遠端狀態（VPS、容器、伺服器）的指令，軍師大腦在轉交給終端機之前，必須先做「安全體檢」。

**三道必加護欄：**

1. **動手前備份**
   - `cp -r <target> /tmp/<name>_backup_$(date +%Y%m%d_%H%M%S)`
   - 不能光憑「應該不會出事」就動手

2. **防止靜默覆蓋**
   - `cp` 改成 `cp -rn`（no clobber，不覆蓋既有檔）
   - `mv` 前先 `ls` 確認目標不存在
   - `rm -rf` 前先確認路徑變數不為空（`[ -n "$path" ] && rm -rf "$path"`）

3. **動後實質驗證**
   - 不要只信 `docker ps | grep healthy`，要真的打健康端點看 HTTP 200
   - 重要檔案搬完後，要 `[ -f <path> ]` 確認落在預期位置
   - 修完後跑一次該功能的最小測試，不是看狀態標籤

**Why:** 教練在 2026-05-08 觀察到 Mac 端終端機產的指令直接 `cp -r` + `rm -rf`，沒備份就動手。一旦覆蓋到外層的修改版本，就再也救不回來了。執行者離鍵盤近、追速度；軍師大腦是策略守門員，本來就該負責把護欄補上。這不是質疑終端機的能力，是分工的本質。

**How to apply:**
- 收到任何含 `cp -r`、`mv`、`rm -rf`、`chown -R`、`docker restart`、`git reset --hard` 的指令時，自動觸發體檢
- 體檢三問：①壞了能不能還原？ ②會不會悄悄覆蓋既有檔？ ③驗證的方式是表面標籤還是實質測試？
- 任何一問答不上來，就要先補護欄再轉交給終端機
- 寫指令包時把「還原指令」也附上，讓終端機壞了立刻能救
