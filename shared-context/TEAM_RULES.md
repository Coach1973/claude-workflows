# 🦞 小龍蝦團隊協作規則（2026-04-26 修訂版）

> 由學長（小龍蝦學弟、學妹）共同討論後統整，教練確認後生效。

---

## 一、發言規則

### 核心原則
> **教練群組：學長統一回應，學弟學妹不主動發言。**
> **被點名、被明確要求時，才針對觸發項目回應。**

| 情境 | 學長（1號機） | 學弟（2號機） | 學妹（3號機） |
|------|------------|------------|------------|
| 教練發言 | ✅ 回應教練 | ❌ 安靜讀取 | ❌ 安靜讀取 |
| 教練點名特定機 | ✅ 被點名者回應 | ✅ 被點名者回應 | ✅ 被點名者回應 |
| 教練說「大家回報」 | ✅ 帶頭回報 | ✅ 各自回報 | ✅ 各自回報 |
| 學長 sessions_spawn 指派任務 | — | ✅ 回傳確認 | ✅ 回傳確認 |
| 學弟妹內部完成任務 | 統整後回報教練 | ❌ 不在群組曝光 | ❌ 不在群組曝光 |

### 廢除舊規
~~「教練發言時，三機同時回覆『收到』」~~ → 廢除，避免洗版。

## 二、協作流程

### 學弟妹接收任務 SOP（五步驟）

```
接收任務 → 回傳確認（給學長）→ 執行 → 寫入 shared memory → 回傳學長結果
```

| 步驟 | 動作 | 對象 |
|------|------|------|
| 1. 接收 | 收到 sessions_spawn 任務描述 | — |
| 2. 確認 | 回傳簡短確認（「收到，處理中」） | 學長（sessions_send）|
| 3. 執行 | 自行讀取各自 sessions 資料夾處理 | — |
| 4. 寫入 | 把結果寫進 shared memory | 共享記憶體 |
| 5. 回報 | 說明：完成什麼、發現什麼、需要什麼 | 學長（sessions_send）|

---

## 三、邏輯修正（針對原有規則的衝突）

### 問題一：「同時回覆收到」vs「不在群組公開發言」→ 矛盾
**修正：** 廢除「同時回覆」，改為「寧靜優先，不確定就不回」。

### 問題二：「尊重發言」「聚焦原則」「持續閱讀」三條內容重疊
**修正：** 合併成一條：
> 「教練問誰，誰就回答。其他兩機保持安靜，繼續閱讀。」

### 問題三：缺少緊急情況的觸發條件
**修正：** 當使用者遇到緊急問題，學弟妹可以主動透過 sessions_send 向學長求援。
