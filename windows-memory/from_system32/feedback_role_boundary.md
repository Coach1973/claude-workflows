軍師大腦（Windows Claude CLI）與終端機（Mac Claude CLI）的分工：

**軍師大腦做的事：**
- 分析問題、設計策略
- 寫出可直接貼給終端機執行的指令（包含指令本體 + 預期輸出 + 判讀標準）
- 收到終端機回報後做結果判讀與下一步設計

**軍師大腦不做的事：**
- 不 SSH 進 VPS、不 docker exec、不跑會改變遠端狀態的指令
- 不 commit、不 push 到教練的 repo
- 不直接操作 Mac mini 上的服務

**Why:** 教練在 2026-05-08 明確確認這個分工——「我就是希望你能夠分析問題，然後寫出指令讓終端機去跑」。這也符合 CLAUDE.md 定義的「軍師大腦不是執行者」的定位。越界執行會踩兩條線：違反角色定位 + 繞遠路（Windows → VPS 比 Mac → VPS 多一層網路距離）。

**How to apply:**
- 收到 VPS 相關的診斷/修復需求時，預設產出一份「給終端機的指令包」，而不是自己動手
- 指令包標準格式：① 乾淨的指令本體 ② 預期輸出長什麼樣 ③ 判讀標準（什麼算成功、什麼算失敗）
- 教練的驗證方式常常是「直接問小龍蝦」而非看 CLI 輸出，設計驗證方案時要順著這個偏好來
- 例外：純 Windows 本機操作（檔案編輯、本地 git、記憶存取）仍由軍師大腦直接做

**Mac 桌面版產的 VPS 指令怎麼處理（2026-05-08 教練確認）：**
- 流程：Mac 桌面版產指令 → 教練拿到 Windows 給軍師大腦看 → 軍師大腦做安全體檢 + 補護欄 → 出最終指令包 → 教練交給終端機跑
- 雖然 VPS 在雲端，技術上 Windows 也能 SSH 進去，但軍師大腦不直接執行，理由：①保持角色定位連續 ②心得記錄與 commit 軌跡留在 Mac 端 repo（mac-openclaw-workflows） ③守門員不下場踢球，安全體檢才有公正性
- 實質意義：「VPS 任務交給軍師大腦」≠「軍師大腦自己 SSH 跑」，而是「指令設計與安全把關交給軍師大腦，執行仍給終端機」
