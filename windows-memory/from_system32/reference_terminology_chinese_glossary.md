# 軍師術語中文對照表

> **使用方式**：軍師寫回應前自己對照一次，沒對應就用比喻講；教練看不懂時直接查這份。

## 一、Git 版本控制（最常用，教練每天看到）

| 英文 | 中文 | 白話解釋 | 生活比喻 |
|------|------|---------|---------|
| repo / repository | 倉庫 | GitHub 上存放檔案 + 歷史的地方 | 像是雲端硬碟，但會記得每一次的修改 |
| commit | 提交 / 存檔點 | 把改動「打包封存」成一個歷史紀錄 | 像玩遊戲存檔，存了就能回讀 |
| commit hash | 存檔點編號 | 每個 commit 的獨一無二代號（一串字母數字） | 像每張發票的流水號 |
| commit message | 存檔點說明 | 寫這次存檔做了什麼、為什麼 | 像存檔旁邊的便利貼 |
| push | 推上去 | 把本機的存檔點上傳到雲端（GitHub） | 像把本機檔案上傳到 Google Drive |
| pull | 拉下來 | 從雲端把別人新增的存檔點下載到本機 | 像同步更新最新版 |
| fetch | 抓資訊 | 只看雲端有什麼新東西，但**還不真的下載合併** | 像先看訊息預覽，但不打開 |
| rebase | 重新接軌 | 把本機改動「移植」到雲端最新版的後面 | 像錯過早班車，搭下一班接著走 |
| merge | 合併 | 兩條歷史線匯成一條 | 像兩條河匯流 |
| HEAD | 目前位置 | 本機現在指向哪個存檔點 | 像書籤夾在哪一頁 |
| main / master | 主線 | 倉庫的主分支（最重要那條歷史線） | 像書本的正本 |
| branch | 分支 | 從主線分出去的平行歷史線 | 像影印一份去改，改完再決定要不要合回正本 |
| origin | 雲端來源 | GitHub 那邊的版本 | 「雲端那一份」的代稱 |
| working tree | 工作區 | 目前正在改的檔案狀態 | 桌面上攤開的稿子 |
| staged | 已暫存 | 已挑出來要打包的改動 | 已疊好準備裝箱的物品 |
| stash | 暫存 / 暫放 | 把目前的改動先收起來不打包 | 像把手上的東西先擱抽屜 |
| diff | 差異 | 兩個版本之間改了什麼 | 像兩張稿子的紅筆對照 |
| status | 狀態 | 目前有哪些改動還沒打包 | 像現在桌上有哪些東西沒收 |
| conflict | 衝突 | 兩個版本同一處改不一樣，要人來決定 | 像兩個人改同一段話、要協商哪版留 |
| force push | 強推 | 強制覆寫雲端 | **危險！等於拿橡皮擦塗掉別人的歷史** |

## 二、系統定時任務

| 英文 | 中文 | 白話解釋 |
|------|------|---------|
| cron | 系統鬧鐘 | Mac 內建的定時器，每分鐘檢查一次「現在該跑哪些任務」 |
| crontab | 鬧鐘設定表 | 列出「幾點跑什麼程式」的清單 |
| `* * * * *` | 每分鐘 | 五個欄位代表 分／時／日／月／星期 |
| `*/15 * * * *` | 每 15 分鐘 | 第一欄寫 */15 就是每 15 分鐘一次 |
| LaunchAgent | Mac 專屬鬧鐘 | Mac 比 cron 更現代的定時系統 |
| plist | 設定檔 | LaunchAgent 的設定格式 |
| log | 紀錄檔 | 程式跑過留下的文字紀錄 |
| /tmp/ | 暫存資料夾 | Mac 系統的「暫放」資料夾，重開機會清空 |

## 三、Claude / API / 模型

| 英文 | 中文 | 白話解釋 |
|------|------|---------|
| CLI | 命令列 / 終端機 | 黑底白字打指令的視窗（不是 GUI 點按鈕） |
| GUI | 圖形介面 | 用滑鼠點按鈕的視窗（有顏色、有圖示） |
| Claude Code | Claude 寫程式版 | 教練裝在 Mac 的 Claude，能讀寫檔案、跑指令 |
| `claude --print "問題"` | 一次問一次答 | 從終端機叫 Claude 回答一個問題就結束，不開對話 |
| API | 應用程式介面 | 程式跟服務溝通的窗口，類似「網路上的客服專線」 |
| API Key / Token | 通行證 / 通行碼 | 一串字串，證明你有權使用這個服務 |
| base URL | 服務網址 | API 服務的入口網址 |
| OAuth | 授權登入 | 用瀏覽器跳轉、按「允許」的登入方式 |
| prompt | 提示 / 指令 | 給 AI 的輸入訊息 |
| system prompt | 系統提示 | 預先寫好給 AI 的「你是誰、要做什麼」的設定 |
| session | 對話階段 / 場次 | 一次完整的對話，有開始有結束 |
| context | 上下文 / 對話記憶 | AI 這場對話記得的所有內容 |
| context window | 對話記憶上限 | 一場對話最多能記多少字 |
| token | 字符單位 | AI 處理文字的最小單位，1 token 約 0.7 個中文字 |
| model | 模型 | AI 的版本，例如 Opus / Sonnet / Haiku |
| Opus | 旗艦版 | 最強最貴的 Claude（軍師用的） |
| Sonnet | 中階版 | 中等聰明、便宜 5 倍（終端機用的） |
| Haiku | 輕量版 | 最快最便宜的 Claude |
| middleware / 中轉商 | API 代理商 | 在我們和 Anthropic 原廠之間的中間人，可能有不同價錢與限制 |

## 四、Relay 派工系統（B 階段考古重點）

| 英文 | 中文 | 白話解釋 |
|------|------|---------|
| relay | 派工 / 接力 | AI 之間互相派任務的系統 |
| queue | 佇列 / 派工單箱 | 等待處理的任務排隊清單 |
| `RELAY_QUEUE.json` | 派工單箱檔案 | 所有派工單的儲存位置 |
| relay_submit.py | 送派工單程式 | 把新任務寫進派工單箱 |
| relay_poll.py | 輪詢派工單程式 | 每分鐘檢查派工單箱有沒有新任務 |
| pending | 待辦 | 派工單剛送進來、還沒被處理 |
| processing | 處理中 | 派工單被認領、正在做 |
| done | 完成 | 派工單已處理完畢 |
| task type | 任務種類 | 派工單上標記要怎麼處理的標籤 |
| handler | 處理程序 | 對應每個任務種類的執行流程 |
| `claude_exec` | 叫 Claude 動腦處理 | 一種任務種類，意思是「把這個 prompt 丟給 claude --print 處理」 |
| `default` | 預設 / 未指定 | 提交派工單沒寫種類時的預設標籤（目前沒對應處理流程，只會被歸檔） |
| worker | 工作者 / 執行者 | 真正處理任務的角色（可能是 Claude、可能是腳本） |
| poll / polling | 輪詢 | 反覆檢查「有沒有新東西」的動作 |
| headless | 無頭 / 沒人值守 | 程式自己跑、不需要使用者在場 |

## 五、檔案 / 路徑

| 英文 | 中文 | 白話解釋 |
|------|------|---------|
| path | 路徑 | 檔案在電腦裡的位置（像住址） |
| absolute path | 絕對路徑 | 從根目錄寫起的完整位址（`/Users/bymyway/...`） |
| relative path | 相對路徑 | 從當前位置開始的位址（`scripts/relay_poll.py`） |
| `~/` | 家目錄 | 個人資料夾的簡寫，等於 `/Users/bymyway/` |
| `./` | 當前資料夾 | 「這裡」 |
| `../` | 上層資料夾 | 「上一層」 |
| symlink | 捷徑 | 像桌面捷徑，指向另一個檔案的指標 |
| JSON | 一種資料格式 | 用 { } 大括號包起來的結構化資料 |
| JSONL | 一種紀錄格式 | 每行一筆 JSON，常用來存對話紀錄 |
| mtime | 最後修改時間 | 檔案最後一次被改的時間 |
| snapshot | 快照 / 整份備份 | 把某個瞬間整份檔案存起來 |
| backup | 備份 | 另存一份保險用的副本 |

## 六、其他常用

| 英文 | 中文 | 白話解釋 |
|------|------|---------|
| env / environment variable | 環境變數 | 程式啟動時讀的「設定值」 |
| shell | 殼層 / 命令環境 | 終端機裡執行指令的環境（Mac 預設是 zsh） |
| Bash / zsh | 兩種殼層 | 講同一件事的不同方言，Mac 預設用 zsh |
| PATH | 程式查找路徑 | 系統去哪些資料夾找指令 |
| process | 進程 / 程式 | 一個正在執行中的程式 |
| spawn | 開啟子程式 | 一個程式啟動另一個程式 |
| `--print` | 一次性印出 | 跑完印結果就結束，不互動 |
| `--rebase` | rebase 模式 | 拉雲端版本時用「移植」方式而不是「合併」 |
| `-p` | 短寫的 prompt | 命令列裡用 -p 指定 prompt |
| dry run | 試跑 | 假裝跑一次但不真的執行，看會發生什麼 |
| race condition | 競爭狀況 | 兩個程式同時動同一份東西、誰先誰後不一定 |

## 軍師自我檢查清單（每次回應前掃一遍）

1. 整段回應有沒有「沒翻譯的英文術語」？有 → 補中文白話
2. 有沒有出現本檔沒列的新術語？有 → 答完後補進本檔
3. 路徑、程式碼、檔名保留英文（這些翻譯沒意義）
4. 教練的命名（SS / ET / MiniMax / 學長學弟學妹）優先使用
5. 「看不懂」是軍師的失職，不是教練的責任
