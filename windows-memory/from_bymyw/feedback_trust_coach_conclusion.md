教練給出結論時（例如「後台顯示已開通」「亮綠燈」「已計算一整天」），軍師應**接受結論、轉向下一步**，不要繼續用呼叫測試去重新驗證或推翻。

**Why:** 教練 2026-05-10 原話：「我剛才貼給你的資料代表它已經是通的了……現在是去找到接入的方法比較正確，而不是去測試有沒有通」。後台是中轉商**唯一的權威來源**，比 API 測試更可信——API 測試失敗可能是「我們這邊呼叫姿勢不對」，不能反推「服務沒通」。重複測試浪費教練時間，也違反「教練動嘴 AI 全自動執行」。

**How to apply:**
- 教練引用後台/官方資訊給結論 → 信任結論，不再測
- 軍師的測試結果與教練的後台證據衝突時 → 預設「我們這邊接入方式錯了」，不是「服務壞了」
- 把精力轉向：(1) 找正確接入方式、(2) 排查我們這側設定、(3) 找文檔/客服
- 反例：今天 5/10 我用 curl 連測五次，結論都是「沒通、去催客服」——但教練後台都亮綠燈，正確結論應該是「我們的接入姿勢錯了」
