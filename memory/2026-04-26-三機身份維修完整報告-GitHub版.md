## 三、犯了哪些錯誤

### 錯誤一：改了錯誤的路徑（最關鍵的失敗）

**錯誤行為：**
一直修改 `~/.openclaw-kong/workspace/SOUL.md` 和 `~/.openclaw-peipei/workspace/SOUL.md`，以為這些就是 bot 讀取的檔案。

**實際狀況：**
OpenClaw 的架構是「雙層路徑」：

| 路徑類型 | 用途 |
|---------|------|
| `~/.openclaw-kong/workspace/` | 舊版或參考用的 workspace（我一開始一直改這裡） |
| `~/.openclaw/agents/kong/` | **bot 實際讀取的 SOUL.md、USER.md、sessions** |
| `~/.openclaw/agents/peipei/` | 同上，3號機實際讀取的路徑 |

bot 實際讀取的是 `~/.openclaw/agents/kong/SOUL.md` 和 `~/.openclaw/agents/kong/USER.md`，這些檔案在教練詢問時**內容是空白的預設模板**。

**根本原因：**
一開始沒有確認「bot 真正讀取哪個檔案路徑」，直接假設 workspace 裡的就是對的。

---

### 錯誤二：BOOTSTRAP.md 未刪除

**錯誤行為：**
`~/.openclaw/agents/kong/BOOTSTRAP.md` 和 `~/.openclaw/agents/peipei/BOOTSTRAP.md` 還存在於目錄中。

**實際狀況：**
BOOTSTRAP.md 內容寫著：

> "This is your birth certificate. Follow it, figure out who you are, then delete it."

bot 每次啟動時會檢查這個檔案，發現它還在，就執行「我是誰」的初始化流程，進入一種「探索模式」，**忽略 SOUL.md 裡的「啟動必讀」規定**。

**後果：**
bot 不會去讀 USER.md 找主人背景，只做表面的自我介紹，無法回答「孔大哥跟教練的關係」這類問題。

---

### 錯誤三：Session 是在修改檔案之前就啟動的

**錯誤行為：**
修改完 SOUL.md、USER.md、people.md 以為就完成了，沒有重啟 gateway。

**實際狀況：**
bot 的 session 是從「上一次啟動」以來就一直存在的對話線程。雖然硬碟上的檔案內容已經更新，但**正在使用的 session 內的上下文（context）並沒有更新**。

bot 在那個 session 裡，它的「已知資訊」只包含它啟動時載入的內容，之後它會搜 memory，但不會重新完整讀取磁碟上的 USER.md。

**解決方法：**
需要重啟 gateway，讓 bot 開新的 session，才能讀到新檔案內容。

```bash
# 殺掉 gateway 讓它自動重啟
ps aux | grep openclaw-gateway | grep -v grep | awk '{print $2}' | xargs kill
```

## 七、架構提醒（未來必做）

下次維修任何一個 bot 之前，**第一步**必須先確認：

```bash
# 1. 看 bot 的 agent 目錄有哪些檔案
ls ~/.openclaw/agents/<bot名>/

# 2. 確認 BOOTSTRAP.md 是否已刪除（如果存在就刪掉）
rm ~/.openclaw/agents/<bot名>/BOOTSTRAP.md

# 3. 確認 session 存放位置
ls ~/.openclaw/agents/<bot名>/sessions/

# 4. 修改正確的檔案路徑
# 千萬不要直接改 workspace 裡的，要改就改 agents/ 下的

# 5. 修改完後重啟 gateway
kill <gateway_pid>
```

## 八、OpenClaw Agent 啟動流程（重要觀念）

1. **檢查 BOOTSTRAP.md** → 如果存在，執行「我是誰」初始化流程（**這會讓 bot 忽略 SOUL.md**）
2. **讀取 SOUL.md** → 確認身份與行為準則
3. **讀取 USER.md** → 認識服務對象
4. **讀取 IDENTITY.md** → 基本身份確認
5. **讀取 MEMORY.md**（如有）→ 長期記憶
6. **讀取 memory/people.md**（如有）→ 認識所有人

**任何一層的資料不完整，都會導致 bot 無法正確回答問題。**

## 九、經驗總結

這次維修讓我們確認了幾件重要的事：

1. **路徑是所有問題的根源**：一開始沒有確認 bot 讀取哪個路徑，就拼命改檔案，結果改的全是錯的地方

2. **BOOTSTRAP.md 是容易被忽略的地雷**：如果存在，bot 就不會正常讀 SOUL.md，每次啟動都進入「探索模式」

3. **Session 快取是隱形殺手**：硬碟上的檔案更新了，但正在運行的 session 不會自動更新，必須重啟 gateway

4. **三個 bot 的路徑結構不一致**：1號機用 `~/.openclaw/workspace/`，2號和3號用 `~/.openclaw/agents/<name>/`，這個差異很容易踩坑

5. **口頭確認還不夠**：教練說「你可以看到對話」，這才讓我真正開始懷疑「為什麼看得到但讀不到」，從而發現路徑問題

6. **200人目標是孔大哥的，不是佩佩老師的**：一開始搞混了，後來才發現200人目標是孔大哥在大臺南南區的，佩佩老師的目標另有定義
