## 一、系統失憶類（導致重複犯錯）

### 案例1：HTML 表單同樣錯誤犯 3 次
**事件**：「送出按鈕不存在 + localStorage 在 file:// 下不work + 刷新後資料消失」教練親自測了3次才完成

**根本原因**：還沒測試就說「刷新就好」「已確認」

**新規則（R13）**：聲稱 DONE 前必須在當下環境實際驗證一次

**正確流程**：
1. 聲稱「已完成」之前，必須在當下環境實際驗證一次
2. HTML 表單三條件：① 送出按鈕真實存在且可點擊、② 按下後教練無需手動複製貼上、③ 重新整理後勾選狀態確實恢復

---

### 案例2：學妹胡亂捏造佩佩老師目標
**事件**：學妹（subagent）在個別對話中「不記得自己是誰、不記得服務對象的目標」，自行生成看起來合理但實際上並非事實的內容

**根本原因**：身份設定只寫在教練的對話框裡，沒有寫入 subagent 各自的 SOUL.md

**新規則**：所有 subagent 回報的「新資訊」必須經教練轉述確認，才能寫入記憶

---

### 案例3：8.5MB = 200萬字（數量級錯誤）
**事件**：小龍蝦說「8.5MB = 200萬字」，教練說「不精準」

**正確做法**：說數字之前，先實際驗證。8.5MB ≠ 200萬字，要確認是 2萬還是200萬。數量級差一個零 = 10倍災難

**新規則**：商務場景的數字必須比教練更嚴格

---

## 二、身份混淆類

### 案例4：三機身份設定失敗
**事件**：學弟、學妹在個別對話中「不記得自己是誰、不記得服務對象的目標」

**根本原因**：
- 身份設定只寫在教練的對話框裡
- 沒有寫入 subagent 各自的 SOUL.md

**正確流程**：
1. 每個 subagent 啟動時必須讀取自己的 SOUL.md
2. SOUL.md 必須包含：我是誰、服務誰、核心守則、協作模式

---

### 案例5：LINE Bot 身份認不出教練
**事件**：LINE 版小龍蝦認不出大樹教練，總是叫成「Richard（蔡曜龍）」

**根本原因**：LINE 沒有 ID 綁定機制，拉進群組就能聊天，但身份辨識系統不完善

---

## 三、技術失誤類

### 案例6： Gemini Empty Response
**事件**：API 返回空回應，但程式碼沒有處理 edge case

**學習**：所有外部 API 回應都必須檢查是否為空再做後續處理

---

### 案例7： DeepSeek Session Lock
**事件**：長任務執行中對話被鎖住，無法繼續

**學習**：
- 長任務需要session_id追蹤
- 需要有恢復機制

---

### 案例8： TTS Quota Drain
**事件**：TTS 配額異常消耗

**學習**：需要監控配額使用量，超過80%必須預警

---

## 四、協作失敗類

### 案例9：學弟妹不回應學長呼叫
**事件**：relay poll 系統每分鐘輪詢，但 BOT_RELAY.json 的讀取有延遲

**解決**：學弟妹必須在收到任務後立刻回應「已收到」並定期更新進度

---

### 案例10：上下文被重置後無法復原
**事件**：對話框文字太多的時候會重新讀取，但系統沒有保存之前的進度

**學習**：需要 heartbeat + HEARTBEAT.md 機制，在上下文被重置後能快速恢復

## 五、血淚踩坑史（GRAND_MISSION.md）

### 第一章：開機第一週（2026-02）
- Mac mini 對新手完全陌生，連基本操作都要學
- 嘸蝦米輸入法安裝困難
- Ollama 本地模型跑不動（硬體不夠）
- GCP 帳單轉移耗時費力
**學到的**：本地模型不實際，雲端 API 才是正解

### 第二章：小龍蝦上線初期（2026-02 ~ 03）
- Chrome 擴充安裝方式不直覺
- 模型選擇沒有依據，憑感覺亂試
- 不知道系統提示會吃掉大量 Token
**學到的**：要先確認模型的 TPM（每分鐘 Token 上限）再選

### 第三章：Groq 限流災難（2026-04-08）
- 把 Groq 設為 Primary 模型
- 小龍蝦系統提示約 57,000 tokens
- Groq 上限 12,000 TPM → 永遠 413 錯誤
**學到的**：接入新模型前，先確認 TPM 上限。Groq 只能跑小任務，不能當 Primary

### 第四章：Session Lock 迷宮（2026-04-11）
- 錯誤訊息：`All models failed: Live session model switch requested`
- 以為是模型問題，換了又換
- 其實是 JSONL 鎖死，只清 sessions.json 不夠
**正確解法**：刪 JSONL + 清 sessions.json + 清 auth cooldown + 重啟 gateway

### 第五章：記憶失憶問題（2026-04-11）
- AGENTS.md 規定啟動時讀 `memory/YYYY-MM-DD.md`
- 但 `memory/` 目錄從未被建立
**正確解法**：`mkdir -p ~/.openclaw/workspace/memory/`

### 第六章：Context Overflow 與記憶銜接（2026-04-11）
- 對話框滿了，中間那段就遺失了
- 書籤機制：記錄「哪個檔案存到哪一行」，溢出時從書籤接著存

## 六、預防機制總結

| 問題類型 | 預防機制 |
|---------|---------|
| 失憶導致重複犯錯 | R13交付前自測、OPE優先搜尋 |
| 身份混淆 | 每個subagent必須有獨立SOUL.md |
| 技術失誤 | 外部API必須檢查空值、長任務需要session追蹤 |
| 協作失敗 | Relay系統 + 心跳機制 |
| 上下文溢出 | 70%/80%預警系統 |
| 數量級錯誤 | 說數字前先實際查驗 |
| Subagent幻覺 | 新資訊必須經教練轉述確認 |
