# 📊 36小時血淚試錯總結報告（4/11 06:00 - 4/12 17:28）

這份報告總結了過去 36 小時內，我們如何因為「瞎猜、繞路、把事情做對」而耗費了教練大量的生命、精力，以及克勞德（Claude）一週 72% 的使用量，最終淬鍊出「做對的事」的偉大架構。

## 一、 我們到底犯了多少錯？（六大核心失誤）

1. **Session Lock（對話鎖死）盲目瞎修**：當 Gemini 免費額度耗盡時，我們以為只要把 DeepSeek 加進備援名單就好。結果系統底層的 `model_change` 機制不斷把對話鎖死在 Gemini。我們瞎試了：重啟 Gateway、刪除 Session 檔、寫排程器定時清理... 等等（錯了 5 次）。
2. **失憶症的錯誤解法（Context 撐爆）**：為了不失憶，我們叫小龍蝦每次開機去讀 `memory/` 裡整天的對話檔。結果檔案超過 50KB 後，直接把 Gemini 的處理能力卡死，導致「空白回應」（Silent Failure）。
3. **模型名稱隨便猜**：AI 在沒有確認的情況下，憑空猜測模型名稱與寫法，導致配置檔寫錯，系統崩潰，白白浪費教練時間重新除錯。
4. **找檔案瞎猜路徑**：因為教練用語音輸入常有同音錯字（如：海比干），AI 卻死腦筋去猜完整路徑，找不到就一直道歉，重複浪費 Token。
5. **過度依賴克勞德（殺雞用牛刀）**：把克勞德（Claude Code）當作一般搜尋或閒聊對象，導致高級 Token 在低級錯誤與無效溝通中迅速消耗（燒掉 72%）。
6. **陷入「把事情做對」的輪迴**：發現錯了就寫補丁、寫腳本來修補，而不是停下來找尋「根本的正確路徑」。

---

## 二、 花了多少時間修正？

*   **Session Lock 修復大戰**：花費約 **2~3 小時**（包含凌晨時段的熬夜）。
*   **失憶症與 Gemini 空白回應除錯**：花費約 **4~5 小時**（在備份與讀取機制間反覆拉扯）。
*   **GitHub 三機同步與路徑排錯**：花費約 **2~3 小時**。
*   **總計耗損時間**：純除錯、修復、試錯的時間高達 **8 到 10 小時**。這還不包含教練的焦慮與溝通成本。

---

## 三、 修正了多少次？（反覆輪迴）

*   Session Lock 相關機制，我們反覆試錯修改了 **5 次**。
*   防失憶架構，我們經歷了「沒有存」→「存了沒讀」→「讀了太大當機」→「輕量化讀取」，至少迭代了 **4 次**。
*   Git 備份腳本，因為不同作業系統（Mac/Win）與路徑問題，來回修改了至少 **6 次**。
*   **總計無效迭代高達 15 次以上**，每一次迭代都在燒 Claude 的額度。

---

## 四、 最後如何達成今天的成果？（五大突破）

我們最終痛定思痛，回歸「一開始就做對的事」，在今天下午達成了以下偉大成果：

1.  **一擊必殺的 Session 修復法**：不再寫腳本繞路。遇到限流，直接改 `openclaw.json` 裡的 `primary` 模型，1 分鐘解決，省下 2 小時的試錯。
2.  **四層防失憶架構（頂級特助架構）**：
    *   設立 `< 5KB` 的 `HEARTBEAT.md` 作為「熱上下文」（重啟只讀這個，不當機）。
    *   設立 `memory/` 作為「長期冷備份」（只存不讀）。
    *   徹底根治了小龍蝦的失憶症與空白回應。
3.  **模型零容忍防呆（第 27 條守則）**：寫入 `validate-models.sh` 腳本，禁止 AI 瞎猜模型名稱，必須驗證存在才能切換。
4.  **Find 第一優先（第 28 條守則）**：遇到找不到的檔案，絕對不猜，第一步直接用 `find` 模糊搜尋，完全解決語音辨識錯字的問題。
5.  **核心思維寫入靈魂**：將「做對的事，而不是把事情做對」寫入 `user_grand_mission.md`。前人走過的路，直接執行；不再自作聰明發明新方法。

這 36 小時、燒掉的 72% Token，換來的是一套**「別人拿去用，絕對不會再踩坑」**的頂級特助底層架構。代價極大，但創造的護城河價值無可估量。
