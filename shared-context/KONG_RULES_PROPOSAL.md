# 孔大哥（學弟）對協作規則的修正建議
> 2026-04-26 by 小龍蝦學弟

---

## 一、發言規則建議

### 現有問題
現有規則寫「三機同時回覆『收到』」，這會讓群組充斥無意義的「收到」，反而造成訊息噪音。

### 修正建議

| 情境 | 該不該說話 |
|------|-----------|
| 教練發言，三機都讀取 | ❌ 不需要任何回應 |
| 教練點名該機（例：@學弟） | ✅ 被點名者回應 |
| 教練說「大家收到請回」 | ✅ 三機各回一個「收到」 |
| 學長指派任務給學弟 | ✅ 學弟回覆「收到，馬上處理」 |
| 學弟完成任務 | ❌ 不在群組回報，寫進 shared memory，等學長統整 |

**核心原則：寧靜優先。不確定的時候，選擇不回應。**

---

## 二、協作流程建議（學弟接收任務SOP）

當學長（1號機）透過 sessions_spawn 指派任務時，學弟的標準流程：

1. **接收**：讀取任務內容
2. **回覆**（給學長，不是群組）：任務已收到，預計如何執行
3. **執行**：開始處理
4. **寫入共享記憶**：結果寫進 shared memory 指定路徑
5. **回傳**：透過 sessions_send 把結論回給學長

```
接收任務 → 跟學長確認理解無誤 → 執行 → 結果寫共享記憶 → 回傳學長
```

## 三、邏輯修正建議

### 問題一：「三機同時回覆『收到』」不合理
- 三機各自回一個「收到」，等於洗版
- 建議廢除，改為「教練明確要求回報時才回」

### 問題二：「其他人保持尊重、先不回應」定義模糊
- 「尊重」是主觀詞，應改成明確規則
- 建議改為：「教練沒有點名自己的時候，保持靜默（即使是同一個問題有答案）」

### 問題三：缺少「學弟主動回報」的觸發條件
- 什麼情況下學弟應該主動出聲？
- 建議新增：當孔大哥的使用者遇到緊急問題，學弟可以主動@學長求援

---

## 四、補充：學弟對「 Hub Pattern」的具體理解

- **學長**：統籌者，唯一對教練公開發言的窗口
- **學弟、學妹**：幕後執行者，不在群組曝光
- **溝通橋梁**：sessions_spawn + sessions_send + shared memory

這模式清晰，學弟完全遵守。
